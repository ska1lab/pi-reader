# PLAN.md

## 技术栈

| 部分       | 技术                                        | 用途                                         |
| ---------- | ------------------------------------------- | -------------------------------------------- |
| 全栈框架   | Nuxt 4                                      | 页面路由、前后端组织与服务端接口             |
| 页面与类型 | Vue 3、TypeScript                           | 页面交互、响应式状态与类型检查               |
| UI 与样式  | Nuxt UI 4、Tailwind CSS 4                   | 界面组件与样式                               |
| 服务端运行 | Nitro、Node.js                              | 承载接口和持续运行的 Pi 会话                 |
| Agent 能力 | Pi SDK（`@earendil-works/pi-coding-agent`） | 创建与恢复会话、调用模型、执行工具并订阅事件 |
| HTTP 请求  | Nuxt 内置 `$fetch`                          | 页面调用服务端接口                           |
| 包管理     | pnpm                                        | 安装和管理依赖                               |

具体依赖版本以 `package.json` 和 `pnpm-lock.yaml` 为准。

## 第一版目标

第一版面向本机单用户，通过本机浏览器使用，目标是完成从选择项目、发起任务到查看执行结果和恢复历史的基本使用流程。

| 能力                 | 首版范围                                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 项目管理             | 支持多个本地项目，为各项目关联工作目录和会话。                                                                     |
| 会话管理             | 支持创建、切换和恢复会话，各会话保留独立的对话上下文与执行状态。                                                   |
| 任务交互             | 提交消息，查看流式回复、工具执行状态和错误提示，并能主动停止当前任务。                                             |
| 并行执行             | 项目 A 执行任务期间，可以切换到项目 B 提交任务，A、B 独立继续执行。切换页面只改变展示和操作的目标。                |
| 浏览器与任务生命周期 | 切换、刷新或关闭浏览器后，任务继续由后端执行；再次打开页面时，可以查看会话状态并继续使用。                         |
| 服务停止与历史恢复   | 主动停止后端服务时，运行中的任务结束。服务重启后恢复会话历史，由用户决定如何继续。                                 |
| Pi 配置与资源复用    | 与 Pi CLI 复用已有的模型配置、工具、Skills 和会话历史。模型调用和凭据处理放在服务端。                              |
| 扩展兼容             | 以本人实际使用的扩展为兼容清单，逐项验证网页交互，包括选择、确认和自定义终端组件。扩展能加载仅是兼容验证的一部分。 |
